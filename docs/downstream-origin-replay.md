# Downstream replay provenance controls

The replay uses the source-pinned `tests/run_source_admission_mutations.py` unittest provenance runner. Baselines require all 71 bodies to be entered and no reported failures; mutations require failures from the selected test body or its explicitly authorized oracle code, with no unauthorized traceback frames. The source helper is checked before and after replay. Earlier replay results retain their original source and must not be rebound to this successor.

The parent creates a per-run nonce file and passes its path in the environment. The helper writes the phase record and an end-of-run sentinel to that file only after unittest returns. The parent requires that record and cross-checks it against stderr: tests run, failure ids, and origin-frame filenames inside the authorized test modules. A replaced or forged stderr transcript, including import-time output followed by `os._exit`, does not qualify as `killed` or `control_pass`. This is still not a sandbox against hostile Python that reads the evidence path or nonce and writes the sentinel itself. The self-mutation harness classifies children from the stdout completion line the helper writes at the same point; it does not create the nonce file.

From the repository root, run `python -B -S tests/run_downstream_origin_mutations.py --output /tmp/downstream-origin-new-run`. It exercises six gate mutation cases (including two distinct controls for the same origin-verdict bypass) and four self-runner mutations with a fresh baseline and mutant child in each mode. The separate `test_downstream_origin_mutations.py` controls cover output, helper identity, case inventory and failure reporting. Outputs are scoped software evidence; they do not establish a complete federation auditor or scientific acceptance.
