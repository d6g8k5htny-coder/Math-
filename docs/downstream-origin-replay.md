# Downstream replay provenance controls

The replay uses the source-pinned `tests/run_source_admission_mutations.py` unittest provenance runner. Baselines require all 71 bodies to be entered and no reported failures; mutations require failures from the selected test body or its explicitly authorized oracle code, with no unauthorized traceback frames. The source helper is checked before and after replay. This bounded check is not a sandbox for hostile Python code. Earlier replay results retain their original source and must not be rebound to this successor.

From the repository root, run `python -B -S tests/run_downstream_origin_mutations.py --output /tmp/downstream-origin-new-run`. It exercises four gate mutations and four self-runner mutations with a fresh baseline and mutant child in each mode. The separate `test_downstream_origin_mutations.py` controls cover output, helper identity, case inventory and failure reporting. Outputs are scoped software evidence; they do not establish a complete federation auditor or scientific acceptance.
