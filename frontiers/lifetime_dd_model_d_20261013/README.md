## What the note states (paraphrase; the note governs)

Here `D := (1/2400)∫_0^∞ k^{−8/3}e^{−12k²}E[γ⁶(I − I_quad)(t, χ₀)] dk` with `I(t, χ₀) = Φ(1 − t, 8 − 12t + χ₀)`, `t = 12kB/γ²`, `χ₀ = 576k²C₃/γ³`, `(γ, B, C₃) ~ N(0,2) ⊗ N(0,2) ⊗ N(0,6)`, `I_quad` the quadratic polynomial of note DC, and `Φ` the closed form of #244 (2.5)–(2.7).

- **Reduction (§1).** `D = ∫du∫dω ρH` over `τ = e^u`, `g = e^ω`, with `ρ = c₀τ^{−5/3}g^{11/3}e^{−12τ²g⁴ − g²/4}`, `c₀ = 1/(2400√π)`, and `H = E[g(σ_tZ₁, σ_χZ₂)]`, `σ_t = 12√2τ`, `σ_χ = 576√6τ²g`, where `g = I − I_quad`; the `v`-form of `Φ` ((1.1), from #244 (2.5)–(2.7)); and the `(t, v)` form `H = (24τ√π)^{−1}∫F dv` with closed-form `t`-moments (1.3).
- **Lemma 1.** A pointwise bound `|g| ≤ g̃(t, χ)` by an explicit polynomial in `|t|`, `|χ|`, `|c′|` and `ρ_R = (R²/16)^{1/3}`.
- **Lemma 2.** The `(u, ω)`-derivatives of `H` fall on the Gaussian kernels: `∂_u^a∂_ω^bH = E[gQ_{a,b}]` with explicit kernel polynomials.
- **Lemma 3.** The degree-11 Taylor polynomial of `g` at the origin (exact rational coefficients) and its remainder constant `C₁₂ = 404.07` on the box `|t| ≤ 3/10`, `|χ| ≤ 1`.
- **Lemma 4.** The tensor 4-point Gauss–Legendre remainder on a cell, with the derivatives of `ρ` bounded through Bell polynomials.
- **Lemma 5.** The `v`-tail: `{v ≥ v₁} ⊂ {|t| ≥ T₁} ∪ {|χ| ≥ X₁}` with explicit `T₁`, `X₁`.
- **Lemma 6.** Closed-form bounds for the `τ`-tail, the `ω`-tails and the region `τ ≤ e^{−6.2}`.

## Replay

    python3 -B -S frontiers/lifetime_dd_model_d_20261013/replay.py
    python3 -B -O -S frontiers/lifetime_dd_model_d_20261013/replay.py

`replay.py` uses the standard library only. A full run takes about 45 minutes per mode, almost all of it in the two assemblies' recomputation checks; `--quick` skips the assembly replays and the node-mutation control (about three minutes). It runs five checks:
1. **Identities.** Every stored file has the identity pinned in `SOURCES.json`, the tree holds nothing else, and there are no symlinks.
2. **The pin.** Every certificate file named in the tables of the stored pinning comments has the byte count and SHA-256 the comment states: the controls comment (23 files) and the controls addendum of record (3 files; the two earlier addenda carry the same table) for `certificate/`, the controls comment v2 (32 files) for `certificate_v2/`.
3. **The replays**, for each certificate, each under the current interpreter's `-O`/`-S` flags, with stdout byte-identical to the stored record and empty stderr: `dd_controls.py` (controls C1–C9, exit 0 iff all pass), `dd_mutants.py` (nine mutants, each rejected), `dd_gapcheck.py` on the stored cells (control C10; no gap in v2) and `dd_exact.py` on the stored cells and node files (the tiling and disjointness checks, every cell remainder recomputed, 24 sampled node values recomputed, `D` and the corollary).
4. **Two negative controls and one output-sensitivity control** (certificate v2). A one-byte change to the stored note is detected. Missing `nodes_11.json` must return exit1, empty stdout and the exact CPython3.11.16 traceback ending `AssertionError: incomplete node values: 2194 of 2393 cells`; only the known certificate directory is substituted into the expected template. This authenticates input-completeness rejection, not mathematical validity. The fixed perturbation of a stored node must return exit0, empty stderr and the exact989byte `CHANGED_NODE_STDOUT`. This runs without recomputation or sampling: output sensitivity, not mathematical rejection. Unrelated crashes, contaminated or incomplete streams and all other results fail. See [scoped verification and remaining boundaries](../../reviews/dd_node_oracle_20261029/VERIFICATION.md).
5. **Named identities.** Each stored verdict, summons and author record names the byte counts and SHA-256 of the stored bodies it refers to: the slice verdicts name v1.0 and the controls comment; the readback summons, the readback verdict, the first read-complete note and the #448 engineering read name v1.0 and v1.1; the C10 summons and verdict name v1.1, v1.2 and the controls addendum; the #449 engineering read and readback name the versions and addenda they hashed; the v1.3 summons and verdict name v1.2, v1.3 and the controls comment v2; the read-complete notes name all the versions they cover (`SOURCES.json`, `names_identities`).

On a child time-out, `replay.py` keeps the partial streams and a `timeout` record in the evidence directory before failing (a point of the Codex review). Certificate v1's `dd_mutants.py` runs its mutated copies of `dd_controls.py` under `-B -S` in both workflow modes; this is by design of that certificate (the controls use `require`, not `assert`, so they are mode-independent, which the controls replay verifies in both modes) and is the known limitation of the v1 mutant lane (the Codex review's second point on Math-#448). Certificate v2's `dd_mutants.py` runs those children in the driver's interpreter mode and keeps the text check under `-O`.

The workflow `.github/workflows/lifetime-dd-model-d.yml` runs on Python 3.11.16, in two jobs, one per mode, each with a 150-minute limit. Each job runs the protocol and raw-evidence tests (`tests/test_lifetime_dd_replay_protocol.py`, 17 tests; `tests/test_lifetime_dd_replay_evidence.py`, 9 tests), the process-oracle tests (`tests/test_lifetime_dd_node_oracle.py`,10methods including real bounded specimens and16source mutants), then the full replay, and retains the raw child streams as an artifact. These finite controls check explicit enclosures and identities, as the reads say. They do not prove the analytic statements.
